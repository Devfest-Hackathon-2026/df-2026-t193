# となりナビ

キオスク端末の前で手が止まる方のための、音声案内 Web アプリです。受付機の画面をスマートフォンで一度撮ると、次に押すボタンを声と画面で案内します。ボタンを押すのは、いつもご本人です。

カテゴリ: 医療・福祉

| URL | 内容 |
|---|---|
| https://axial-sunup-488315-k1.web.app/ | 実カメラで撮影し、Gemini で画面を確認して案内します |
| https://axial-sunup-488315-k1.web.app/demo | 見本モード。AI は使わず、サーバーなしで流れを確認できます |
| https://axial-sunup-488315-k1.web.app/mock/hospital | タブレット等に表示するデモ用の模擬受付機。個人情報は入力しません |

**対応しているのは、登録済みのデモ用模擬受付機（病院の再来受付）だけです。** 実在の機器には対応していません。

## 課題

病院の受付機のようなキオスク端末は、次に何を押せばよいか分からないと先に進めません。対象は端末に不慣れな 50〜70 代の方で、最も難しい 70 代を基準に設計しました。

## 使い方

1. 受付機の最初の画面を一度撮ります。
2. どの画面かを確認し、押すボタンを声と画面で案内します。
3. 押したら「押しました」をタップすると、次の案内に進みます。
4. 診療科はご本人が選びます。アプリからおすすめはしません。
5. 個人情報の入力の前で案内を止め、ご自分で入力していただきます。

## 設計の理由

**AI の役割を「いま、どの画面か」の判定に限定しています。** 次に押すボタンは、AI に作らせず、人が確認した手順データ（[`flows/`](flows/hospital-recheck.json)）から決めます。誤った案内をすると、ご本人が誤った操作をしてしまうためです。

| Google の技術 | 使いどころ | 選んだ理由 |
|---|---|---|
| Gemini 3.5 Flash（Vertex AI） | 撮影した画面の判定 | 角度や明るさの異なる写真から画面を見分けるため。API キーを使わず、サービスアカウントで呼び出します |
| Cloud Run | API サーバー | 使うときだけ起動し、待機中の費用がかからないため |
| Firebase Hosting | Web アプリの配信 | スマートフォンのカメラを使うには HTTPS が必要なため |
| Cloud Text-to-Speech（Chirp 3 HD） | 案内音声の事前生成 | 端末による声の差をなくし、内容を確認した音声だけを流すため |
| Secret Manager | セッション署名鍵の保管 | 鍵をコードや設定ファイルに置かないため |

構成は[アーキテクチャ](docs/03-architecture.md)にまとめています。

## 安全のためのルール

- アプリは受付機を操作しません。
- 個人情報の入力画面や、登録されていない画面では案内しません。自信がないときは撮り直し、またはスタッフへの相談に進みます。
- Gemini の回答は、登録済みの画面 ID などの決められた値だけを受け付け、サーバーと Web の両方で検証します。
- アプリのコードは写真を保存せず、ログにも残しません。
- 診療科のおすすめや症状の相談には答えません。

## 未確認のこと

- 実際のスマートフォンで撮った写真での判定精度と、iPhone / Android の実機動作は確認中です。これまでの通し確認は、模擬受付機の画面を入力にしたものです。
- 高齢の方に対する効果は検証していません。

## 開発

```sh
npm ci
npm run dev      # Web
npm run dev:api  # API（apps/api/.env.example を参照）
```

```sh
npm test
npm run typecheck
npm run build
npm run format:check
npm run test:e2e
```

E2E はインストール済みの Google Chrome を使用します。カメラ映像・API 応答・音声再生はテスト用で、実機検証の代わりではありません。

案内の文言を変えたら、`npm run voice:generate` で音声を作り直します。

```sh
npx firebase-tools deploy --only hosting
```

  このリポジトリでは **GitHub Actions と GitHub Pages が使えません**。CI やデプロイ、Pages での公開をしたいときは、チームで開発用のリポジトリを別に作ってください。

  ## 秘密情報をコミットしない

  API キー・パスワード・サービスアカウントの鍵などは、**絶対にコミットしないでください**。公開リポジトリなので、push
  した時点で誰でも見られます。開発用のリポジトリから持ってくるときも、履歴ごと push すると、過去のコミットに含まれる秘密情報も公開されます。

  - 秘密情報は `.env` や `.dev.vars` などに書き、コミットしない（`.gitignore` に入れてあります）
  - 誤って push したら、すぐにキー（鍵）を無効にして作り直し、運営に連絡してください。履歴から消すだけでは不十分です
  - GitHub の push protection が、よく知られた形式のキーの push を止めることがあります。止められたら、そのキーをコミットから外してください
