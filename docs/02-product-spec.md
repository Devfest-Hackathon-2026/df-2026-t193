# 제품 스펙

## 제품 정의

고령자가 키오스크 첫 화면을 폰으로 한 번 찍으면, **미리 학습한 절차를 따라 멈춰야 할 단계까지 음성으로 안내하는 웹앱**이다. 버튼은 항상 본인이 누른다.

- **이름:** となりナビ (가칭)
- **카테고리:** 의료·복지. 고령자의 디지털 소외 문제를 다룬다.
- **대상:** 키오스크가 낯선 일본의 50~70대. 가장 어려운 사용자인 70대를 기준으로 설계한다.
- **미래 목표:** Gemini로 절차 학습을 자동화해 더 많은 키오스크로 넓힌다.

## 대상 범위

| | 병원 접수기 | 맥도날드 키오스크 |
|---|---|---|
| **역할** | 피치의 메인 문제 | 일상 사례, 확장 가능성 증명 |
| **범위** | 재진 접수 1개 | 단품 주문 1개, 시간이 남으면 세트 |
| **기기** | 허가가 없으면 모의 기기 | 허가가 있으면 실제 매장, 없으면 모의 기기 |
| **멈추는 지점** | 진찰권·보험증 등 개인정보 입력 전 | 결제 직전 |

병원 흐름을 끝까지 지킨다. 일정이 밀리면 맥도날드 세트, 맥도날드 전체 순서로 줄인다.

## 사용 흐름

1. 「はじめる」를 누른다.
2. 첫 화면을 찍으면 어느 기계의 어느 화면인지 식별하고 카메라를 끈다.
3. 앱이 음성과 화면으로 다음 버튼을 안내한다.
4. 사용자가 누르면 조작음을 인식해 다음 안내로 넘어간다.
5. 고를 게 있으면 묻고, 말이나 터치로 답을 받는다.
6. 개인정보 입력이나 결제 전에 멈추고, 본인이 직접 진행하게 한다.
7. 끝나면 마이크를 끈다.

## 문제가 생겼을 때

| 상황 | 동작 |
|---|---|
| 조작음을 못 들음 | 「押しました」로 다음 안내 |
| 화면이 다름 | 「困ったとき」 → 「違う画面です」 → 다시 한 장 찍어 위치 찾기 |
| 첫 식별 실패 | 다시 촬영 |
| 두 번 실패, 미등록 기계 | 직원에게 보여줄 화면 |
| Live 연결 실패 | 터치 선택으로 계속 |

## 왜 Gemini 앱이 아닌가

Gemini 앱은 지금 보이는 화면만 보고 답한다. 이 앱은 그 기계의 전체 절차를 미리 알고 끝까지 데려가며, 위험 단계의 멈춤을 서버 규칙으로 강제한다.

같은 사진과 과제로 Gemini 앱과 직접 비교한 결과를 문서에 넣는다. **이 비교는 아직 하지 않았다.**

## Gemini 역할

| 기능 | 모델 | 쓰는 곳 |
|---|---|---|
| 화면 식별 | `gemini-3.8-flash` | 첫 촬영, 재식별 |
| 절차 학습 | `gemini-3.8-flash` | 화면 사진으로 절차 지도 초안 생성 |
| 음성 대화 | `gemini-3.8-live` | 진료과·메뉴 선택 |
| 안내 음성 | `gemini-3.8-flash-tts` | 음성 사전 생성 |

조작음 인식은 폰에서 처리해 음성을 계속 서버로 보내지 않는다.

## 안전 규칙

**공통**

- 앱은 키오스크를 조작하지 않는다.
- 사진과 음성은 저장하지 않고, 마이크는 안내 중에만 켠다.
- 미등록 기계나 판단이 불확실한 화면은 짚지 않는다.
- 비밀번호와 카드 정보는 읽거나 다루지 않는다.
- ATM과 송금은 안내하지 않는다.

**병원**

- 진찰권 번호, 이름, 보험 정보는 읽거나 저장하지 않는다.
- 진료과 추천과 증상 상담은 하지 않고, 사용자가 말한 진료과만 안내한다.

**맥도날드**

- 결제를 대신 판단해 권하지 않는다.
- 알레르기와 건강 질문에는 답하지 않고 직원에게 넘긴다.

## 합격 기준 (임시값)

- 등록 화면 첫 촬영 식별: 기계별 20회 중 18회 이상
- 두 기계 혼동: 0회
- 병원 재진 접수 완주: 음성 안내만으로 10회 중 9회 이상
- 맥도날드 단품 주문 완주: 10회 중 8회 이상
- 조작음 오인: 소음 조건 10회 시험 후 자동 진행을 기본값으로 할지 결정
- 위험 단계 멈춤과 미등록 기계 거절: 항상 동작

## 주요 결정 기록

| 결정 | 이유 | 버린 안 |
|---|---|---|
| 한 번 촬영 + 사전 학습 절차 | 해커톤은 특정 기기에서 확실히 동작하면 충분하고, 일반화는 미래 목표로 둔다 | 화면마다 재촬영, 카메라 상시 감지 |
| 폰으로 사용 | 사용자가 정한 방향 | 키오스크 옆 고정 단말 |
| 사전 절차 + 조작음 | 소리만으로 처음 보는 화면을 예측할 수는 없지만, 절차를 알면 진행 신호로 쓸 수 있다 | 소리만으로 다음 행동 예측 |
| 짚어 주기만 함 | 본인 의사가 필요한 조작이 많고 대신 조작은 위험하다 | 대신 누르기 |
| 맥도날드 + 병원 | 일상 사례와 복지 문제를 함께 보여준다 | 맥도날드 단독 |
| 음성이 주 안내 | 사용자의 눈은 키오스크에 있어야 한다 | 화면 중심 안내 |
| `village-hall` 코드 미사용 | 시작 전 코드 금지 규칙 | 기존 스타트업 코드 재사용 |

## 소프트웨어로 해결할 수 없는 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 맥도날드 메뉴·프로모션 변경 | 절차 지도가 낡아 틀린 안내 | 대상 흐름을 좁히고, 변경 시 사람이 다시 수집 |
| 병원 촬영 불가·환자 노출 | 실제 화면 확보 불가 | 모의 기기 사용 |
| 병원 모의 기기의 현실성 부족 | 설득력 하락 | 공개 자료와 현장 관찰로 작성, 출처 기록 |
| 맥도날드 촬영 거절 | 실제 영상 사용 불가 | 로고 없는 모의 기기로 대체, 「맥도날드에서 동작」이라고 말하지 않기 |
| 상표·UI 권리 | 저작물 시트 문제, 심사 위험 | 로고·화면 복제 금지, 사용 범위를 Discord에서 확인 |
| 데모 영상 위장 판정 | 심사 대상 제외 | 등록 기기 한정과 모의 여부를 영상에 명시 |
| Gemini 비중이 작아 보임 | 기술 활용 점수 하락 | 식별, 절차 학습, 음성 대화를 데모와 문서에서 강조 |
| 일정 부족 | 기능 미완성 | 우선순위대로 축소 |
| 고령자 미검증 | 효과를 주장할 수 없음 | "연구 근거로 설계했다"까지만 말하기 |
