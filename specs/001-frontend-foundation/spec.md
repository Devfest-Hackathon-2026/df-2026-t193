# となりナビ 프론트엔드 구현 스펙

상태: **프론트 구현 완료, 서버 연결·음원 연결 완료 — 실제 폰 검증 대기**
작성/갱신: 2026-11-08 JST. 구현·검증의 현재 근거는 [frontend-status](../../docs/frontend-status.md)를 따른다.

> 2장의 현재 상태와 3장의 범위 구분은 스펙을 처음 쓴 시점의 기록이다. 이후 `apps/api`가 추가되어 main에 머지됐고, 웹은 Cloud Run API에 연결·배포됐다.

## 1. 목표와 기준

승인한 모바일 디자인을 실제 React 앱으로 옮기고, 고령 사용자가 등록된 모의 병원 접수기의 시작부터 안내 종료까지 진행할 수 있게 한다. 정상 흐름뿐 아니라 권한 거부, 식별 실패, 잘못된 화면, 음성 실패에서도 사용자가 다음 행동을 알 수 있어야 한다.

**디자인을 다시 만들지 않는다.** [승인 시안](../../docs/design-baseline/index.html?view=start&revision=screen-family)의 시작·촬영·안내·선택·완료 화면을 기준으로 한다. 이미지 생성은 사용하지 않는다. 기존 로컬 문서의 큰 색 면, 상단 지시 구역, 48px 제목·88px 버튼 강제 규칙은 사용자 결정에 따라 대체한다. 제품의 안전 규칙은 유지한다.

이 문서가 이번 프론트 구현 범위의 기준이다. 기술 구조는 [plan.md](plan.md), 연결 규격은 [contracts.md](contracts.md), 실행 순서는 [tasks.md](tasks.md)를 따른다. 구현 기준 문서는 저장소의 `specs/001-frontend-foundation/`에서 관리한다. 작업공간 outputs의 문서는 최초 검토용 스펙이며, 구현 진척은 저장소 문서와 검증 기록을 따른다.

## 3. 범위와 완료 단계

### A. 서버 없이 완성하는 프론트

- 승인 UI의 React 이식, 공통 컴포넌트·일본어 문구 정리.
- 실제 카메라 프리뷰·한 장 촬영·권한 및 오류 처리·자원 해제.
- 병원 3개 진료과 분기, 선택 확인, 개인정보 전 멈춤, 재촬영, 도움, 직원 화면, 종료.
- 안내 음성 재생기와 실패 시 터치 진행. 검증용 음원으로 재생 동작을 확인하며 최종 일본어 음원은 별도 준비 상태를 표시.
- 명시적인 견본 모드와 실제 연결용 인터페이스. API 응답·지연·오류를 재현하는 테스트용 서버 대역.
- 별도 `/mock/hospital` 모의 접수기. 폰과 같은 등록 절차·버튼 배치를 사용.
- 접근성·모바일 레이아웃·상태 전이·계약 테스트.

### B. 백엔드가 준비되면 검증하는 연결

실제 세션 발급, JPEG 식별, 검수된 절차 조회, 최종 음원 제공. 프론트 계약 테스트 통과와 실제 서버 연결 성공을 따로 기록한다. 실제 식별 성능·서버 사진 폐기·인증 강제는 프론트만으로 증명할 수 없다.

### C. 사용 가능한 제품 판정

iPhone Safari 및 Android Chrome 실기에서 HTTPS 촬영·음성·전체 흐름을 확인해야 한다. 고령자 사용성은 별도 사용자 검증이며, 미실시 상태에서는 효과가 입증됐다고 말하지 않는다.

이번 필수 범위 밖: 조작음 자동 진행, 마이크/Live 대화, 진료과 추천, 자유 질문, 맥도날드 흐름, 오프라인 절차 캐시, PWA 설치 유도, Wake Lock, AI 모델·백엔드 구현, 배포. 기존 장기 계획에서 삭제하는 것은 아니며 후속 단계로 남긴다.

## 4. 화면별 사용자 계약

| 화면 | 보이는 핵심 | 주 행동 | 뒤로·실패 동작 |
|---|---|---|---|
| 시작 | 로고, 큰 키오스크 장면, `押すボタンを声で案内` | `はじめる` | 사용법은 보조 시트. 권한은 진입 시점에만 요청 |
| 촬영 | 실제 카메라 영상, 노란 가이드, `画面を映してください` | 준비되면 `撮る` | 준비 전 촬영 불가. 취소하면 처음 또는 재촬영 출발점으로 복귀 |
| 식별 중 | `画面を確認しています`와 진행 중 표시 | 취소 가능 | 진행률·AI 성공을 꾸미지 않는다. 늦은 결과는 취소 뒤 반영하지 않는다 |
| 안내 | 해당 단계의 키오스크 장면과 목표 표시, `受付を押してください` | `押しました` | 가벼운 음성 재생 행, 확대, `困ったとき` |
| 선택 | `どの科ですか？`, 내과/외과/정형외과 라디오 | 선택 후 `内科で進む` 등 | 기본 선택 없음. 항목 터치는 선택만 변경; 확정 전 진행 없음 |
| 개인정보 멈춤 | `ここからはご自分で`와 번호를 말하지 않도록 안내 | `入力しました` | 이전 안내 확인은 가능하나 멈춤 통과로 처리하지 않음. 입력 폼 없음 |
| 도움 | `違う画面です`, 직원에게 보여주기 | 선택한 복구 경로 | 닫으면 단계 유지. 배경 조작 차단 |
| 직원 | `操作が分かりません。手伝っていただけますか。` | 처음으로 또는 유효한 이전 안내 | 실제 직원 호출·전송 기능처럼 표현하지 않음 |
| 완료 | `案内はここまでです`, `おつかれさまでした` | `はじめに戻る` | 안내 종료만 의미. 실제 병원 접수 완료를 확인했다고 주장하지 않음 |

연결 모드와 기기 출처는 구분한다. `見本モード`는 가짜 식별 응답을 사용하는 앱 모드, `模擬端末`는 실제 식별 API를 써도 대상 기기가 모의 기기라는 뜻이다. 실제 촬영 화면에 견본 SVG를 카메라 영상처럼 넣지 않는다.

## 5. 디자인을 구현에 고정하는 규칙

**FR-001 — 승인 화면 유지.** 큰 키오스크 장면 위에 흰 하단 안내 패널이 겹치는 구성, 로고, 색 역할, 음성 행, 파란 주 버튼을 유지한다. 화면을 작은 카드/3×3 추상 그림으로 바꾸거나 장식·설명 문단을 늘리지 않는다. 오류 상태는 행동에 필요한 짧은 문장과 복구 버튼으로 확장한다.

승인 파일을 실제로 읽어 추출한 값:

| 항목 | 기준 |
|---|---|
| 지시 제목 | 30px 기준 `1.875rem`, 행간 1.48, 일반 400 / 목표 단어 600 |
| 주 버튼 | 26px, 높이 최소 76px; 높이 720px 이하 화면에서는 72px |
| 음성·도움 | 20px, 터치 높이 음성 48px / 도움 50–54px |
| 선택 항목 | 24px, 행 높이 72px / 작은 높이에서 64px |
| 패널 | 상단 모서리 24px, 장면과 22px 겹침, 좌우 22–24px 여백 |
| 색 | 지시 #146C2E, 폰 응답 #0B57D0, 목표 #FBBC04, 멈춤 #A50E0E |
| 글꼴 | 기존 시스템 일본어 글꼴 스택. 이미지 안에 본문·폰 버튼 글자를 굽지 않음 |

**FR-002 — 장면과 지시 일치.** 각 단계의 목표 명칭·위치·장면·확대가 같은 등록 버튼을 가리켜야 한다. 폰 주 버튼은 실제 키오스크 버튼과 구분한다. 장면은 등록된 기기의 안내용 예시이며 라이브 화면이라고 표현하지 않는다. 첫 사진을 다음 화면처럼 계속 재사용하지 않는다. 등록 장면이 없거나 다른 기기·버전이면 임의 그림으로 대체하지 않고 안내를 중지한다.

**FR-003 — 확대·작은 화면.** 390×844, 360×640의 기본 글자에서 주 행동과 안내 목표가 가려지지 않아야 한다. 200% 글자·확대에서는 세로 스크롤을 허용하되 글자 잘림·겹침·가로 넘침이 없어야 한다. 짧은 화면에서 억지로 맞추려고 글자를 축소하지 않는다. 노치·브라우저 바·가로 회전도 조작을 막지 않아야 한다.

**FR-004 — 접근 가능한 조작.** 모든 조작을 실제 button/radio로 제공하고 색 외의 텍스트·표식으로 상태를 전달한다. 뒤로는 승인 시안의 44px 이상, 그 외 보조 조작은 48px 이상 터치 영역을 유지한다. 화면 전환 시 제목, 시트 열기 시 내부, 닫기 시 호출 버튼으로 초점 이동. 화면읽기·키보드로 선택·취소·복구가 가능해야 한다. 모달 배경은 조작할 수 없어야 한다. 일반 텍스트 대비 4.5:1, 큰 텍스트와 필요한 UI 경계 3:1을 구현 검증 기준으로 제안하며 밝은/어두운 테마 모두 측정한다. 움직임 줄이기와 고대비 설정을 유지한다.

## 6. 동작 요구사항

**FR-005 — 카메라 수명.** 사용자 시작 후 후면 카메라를 우선 요청하고, 준비된 실제 영상만 촬영한다. 카메라 없음·거부·사용 중·보안 연결 부재를 구분한다. 다시 시도는 사용자 행동으로만 한다. 권한 창을 무시해도 앱에서 취소할 수 있어야 한다. 촬영 성공·취소·화면 이탈·앱 숨김·오류 때 트랙을 종료한다. 늦게 허용된 스트림도 현재 촬영 세션이 아니면 즉시 종료한다. 복귀 시 자동 촬영하지 않는다.

**FR-006 — 사진 최소 취급.** 미리보기 방향과 캡처 방향이 일치하며 이미지 비율을 왜곡하지 않는다. 등록 화면 전체를 찍도록 안내하고 주변은 촬영 프레임 밖으로 유도한다. JPEG는 메모리에서 축소·전송하고 저장·로그·분석 이벤트에 넣지 않는다. 전송 완료·실패·취소 시 Blob/URL/캔버스 참조를 정리한다. 재요청에는 새 촬영이 필요하며 사진을 몰래 자동 재전송하지 않는다.

**FR-007 — 정확한 식별 진입.** `ok` 타입뿐 아니라 흐름·기기·화면·첫 단계 ID의 관계, 검수 여부, 장면 버전까지 검증한 뒤 한 번에 안내로 전환한다. 실패 시 기존 안내와 새 데이터가 섞이면 안 된다. raw 모델 문장/HTML을 렌더하지 않는다.

**FR-008 — 안전한 상태 전이.** 활성 화면·단계에 맞는 이벤트만 받는다. 한 번 누르기·빠른 두 번 누르기·취소 후 늦은 응답으로 단계가 두 개 이동하지 않아야 한다. 다음 단계 도착에는 그 단계에서 시작한 새 사용자 조작이 필요하다. 재시작·새 요청 후 이전 요청의 결과는 무시한다. 새로고침은 새 시작으로 돌아가며 민감 데이터·오래된 단계를 복원하지 않는다.

**FR-009 — 선택과 확인 분리.** radio 선택은 임시 선택만 바꾼다. 확정 버튼을 눌러야 현재 단계의 허용 option ID로 진행한다. 선택 없음·알 수 없는 ID는 진행 불가. 진료과를 추천하거나 자동 기본값으로 고르지 않는다.

**FR-010 — 멈춤을 건너뛰지 않음.** 개인정보 단계에는 촬영·마이크·민감 입력 UI가 없다. 안내용 짧은 안전 음성은 가능하나 개인정보를 읽지 않는다. 명시적 `入力しました`만 재개 가능한 stop을 통과한다. 시트 닫기·뒤로·음성 종료·중복 클릭은 통과 신호가 아니다. 재개 불가 stop에는 다음 단계 액션이 없다.

**FR-011 — 음성은 한 번에 하나.** 현재 단계의 검수된 일본어 안내만 재생한다. 재생/중지/재시도를 제공하고 단계 이동·도움·멈춤 전환·백그라운드·완료에서 이전 음성을 중지한다. 재생 불가·음원 없음이어도 터치로 진행 가능하고 재생 중이라고 거짓 표시하지 않는다. 자동 재생 차단 때 사용자가 눌러 재생할 수 있게 한다. 마이크 권한은 이번 범위에서 요청하지 않는다.

**FR-012 — 실패 원인별 복구.** 인식 unknown만 연속 식별 실패 횟수에 포함한다. 첫 unknown은 재촬영, 두 번째는 직원 화면. 네트워크/권한/서버 오류를 unknown으로 변환하지 않는다. timeout·오프라인·401·413·429·5xx·잘못된 JSON에 맞는 복구를 제공한다. 오류에 원본 응답·개인정보·기술 스택을 노출하지 않는다.

**FR-013 — 잘못된 화면 복구.** 재촬영의 출발 단계·선택을 메모리에 보존한다. 취소는 원래 화면을 복원하며 진척을 추가하지 않는다. 새 식별 성공은 등록된 현재 화면의 시작 단계로 바꾼다. 진료과 메뉴 재식별은 선택 화면으로 돌아가며 과거 선택을 확정하지 않는다. 개인정보 화면은 촬영하지 말라는 안내로 처리하며, 서버에서도 민감 화면 거절이 필요하다.

**FR-014 — 견본과 실연결 분리.** 견본은 명시적으로 진입하고 항상 견본임을 표시한다. 실연결 실패를 견본 성공으로 바꾸지 않는다. 일반 실행에서 API 설정이 없으면 연결 준비 상태와 복구 안내를 표시한다. 견본 전체 흐름은 외부 API·토큰·마이크 없이 실행 가능하다.

**FR-015 — 모의 접수기와 일치.** `/mock/hospital`에서 접수→진료과→가상 본인 입력 단계→확정→완료를 실제 터치로 진행할 수 있다. `デモ用の模擬端末` 상시 표시, 실명·번호 입력 없음. 폰 진행 버튼이 모의 기기를 원격 조작하지 않는다. 모의 기기 화면·안내용 SVG의 버튼 위치와 문구를 비교한다.

**FR-016 — 공유 코드와 자료 보호.** 로컬 기존 코드의 사용 시점·출처를 확인해 필요한 소스만 제출 저장소에 편입한다. 기존 원격 파일을 보존한다. node_modules, dist, private 자료, 실제 사진, .env, 키는 포함하지 않는다. 테스트 결과는 대상 코드와 시각을 함께 기록하고 로컬·연결·실기 결과를 구분한다.

## 8. 완료 판정과 남은 결정

- **프론트 구현 완료:** FR-001~016에 대한 로컬 자동화·시각 검증 통과. 실카메라 및 일본어 음성 실기 결과는 별도로 명시. API 대역 통과를 AI 동작으로 보고하지 않는다.
- **연결 완료:** 실제 서버에서 세션→촬영→식별→검수된 flow→안내가 통과하고 오류 계약도 확인됨.
- **실기 확인 완료:** 실제 iPhone/Android의 기종·OS·브라우저·HTTPS URL·결과를 기록. 화면읽기와 소리 확인 포함.
- **미확정:** 팀의 별도 개발 저장소/백엔드 위치, API 배포 주소·페이로드·버전 정책, 최종 음원·공개 가능한 등록 장면. contracts의 제안으로 프론트 대역 구현은 시작 가능하나 서버와의 합의를 대신하지 않는다.
- 기존 문서의 식별 정확도·완주율은 제품 전체의 임시 목표다. 이번 프론트 작업에 검증되지 않은 수치 성과나 일정 보장을 붙이지 않는다.
