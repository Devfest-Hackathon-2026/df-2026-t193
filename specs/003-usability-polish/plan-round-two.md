# 사용성 2차 구현 스펙

상태: **승인, 구현·로컬 검증 완료. 배포 전.** 작성 2026-11-09 JST.

요구사항은 [spec.md](spec.md)의 U8~U14다. 이 문서는 어떻게 구현하는지를 정한다.

## 1. 목표

어르신이 실수해도 되돌릴 수 있고, 키오스크를 보는 동안 폰이 꺼지지 않으며, 작은 화면에서도 도움 버튼이 보이게 한다. 승인된 화면 구성(큰 키오스크 그림, 흰 패널, 파란 주 버튼)은 바꾸지 않는다.

## 2. 구현 항목

| ID | 무엇을 | 어디를 | 어떻게 | 위험과 대응 |
|---|---|---|---|---|
| U8 한 단계 되돌리기 | 도움 시트에 「一つ前の案内に戻る」 | `state/machine.ts`, `App.tsx`, `copy/ja.ts` | 상태에 지나온 단계 목록 `trail`을 추가한다. `BACK`은 마지막 단계로 돌아가고 revision을 올린다. 첫 단계에서는 버튼을 숨긴다. 식별이 새로 성공하면 목록을 비운다 | 개인정보 멈춤 우회: 멈춤 단계로 돌아가면 멈춤 시트가 다시 열리고 「入力しました」를 다시 눌러야 한다. 앞으로 건너뛰는 동작은 없다 |
| U9 화면 꺼짐 방지 | 촬영부터 안내 종료까지 Wake Lock | 새 `hooks/useScreenWake.ts`, `App.tsx` | 시작 화면과 종료 단계를 뺀 동안 요청한다. 앱이 다시 보이면 재요청하고, 끝나면 해제한다. 실패해도 무시하고 진행한다 | 배터리 소모. 안내 중에만 켠다. iPhone 동작은 실기 확인이 필요하다 |

## 3. 바꾸지 않는 것

- API와 Cloud Run 설정, Gemini 프롬프트
- 안내 문장 음원. 새 문구는 화면에만 나오므로 다시 생성하지 않는다
- 진료과의 선택·확정 분리(FR-009)
- 승인된 화면 구성과 색

## 4. 검증 계획

| 항목 | 방법 |
|---|---|
| U8 | 단위: 되돌리기, 첫 단계 무동작, 오래된 revision 무시, 멈춤 재통과 필요. E2E: 도움 시트에서 되돌리기 |
| U9 | E2E(가짜 Wake Lock): 안내 중 요청, 종료 시 해제, 요청 거절 시 정상 진행 |
| U10 | E2E: 도달 전 단계 그림의 요청 확인 |
| U11 | E2E: 375×553, 360×560에서 주 버튼과 「困ったとき」가 화면 안 |
| U13, U14 | E2E: 문구 표시 |
| U12 및 전체 화면 | 390×844, 360×640, 375×553 실제 렌더(소리 없이 헤드리스) |
| 공통 | test, typecheck, format:check, build, test:e2e |

실제 폰 동작과 어르신의 이해 여부는 이 검증으로 확인되지 않는다.

## 5. 결과

단위 테스트 96개, 브라우저 테스트 57개. 375×553과 360×560에서 안내·선택 화면의 주 버튼과 「困ったとき」가 화면 안에 들어온다.

도움 시트는 높이 600px 이하에서 25~32px 넘쳤다. 그래서 이 높이에서만 도움 시트의 자동 읽기 토글을 숨겼고, 사용법 시트에는 그대로 있다.

## 6. 결정 사항 (승인됨)

1. **Wake Lock 범위:** 001 스펙은 Wake Lock을 범위 밖으로 두었다. 이번에 포함할지 정한다. 권장: 포함.
2. **문구 변경:** 「声を止める」, 「科を選んでください」, 「一つ前の案内に戻る」를 승인할지 정한다.
3. **도움 시트 길이:** 되돌리기가 추가되면 항목이 다섯 개가 되어 높이 600px 이하에서 스크롤이 생길 수 있다. 권장: 구현 후 측정해 넘치면 자동 읽기 토글을 사용법 시트에만 둔다.
4. **이미 작성된 코드:** 중단된 명령으로 위 항목의 코드가 `feat/ux-round-two` 작업 폴더에 들어갔다(QR 제외). 테스트 전이고 커밋하지 않았다. 스펙을 승인하면 이 코드를 검증하고, 수정이 있으면 반영한다. 반려하면 되돌린다.
