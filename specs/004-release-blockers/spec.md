# 제출 전 필수 수정 구현 스펙

상태: **승인, 구현·검증 완료. 커밋과 배포 전.** 작성 2026-11-09 JST. 기준은 PR #5가 포함된 main `0b4323e`이다.

## 1. 목표

개인정보 단계에서 잘못된 안내가 나오지 않게 하고, 실수로 진행을 잃지 않게 하고, 태블릿 시연에서 접수기가 화면에 들어오게 한다. PR #5의 화면 구성(진행 표시, 키 모양, 주 버튼 아래 보조 버튼 2개)은 유지한다.

## 2. 진행 순서

1. **M1** 미커밋 2차 보완을 main에 맞춰 병합 (B2가 되돌리기 기능에 의존한다)
2. **B1~B4** 필수 수정, **L1** 작은 화면 배치
3. 전체 검증
4. 커밋, PR, 머지, **웹 배포**는 각각 별도로 확인받는다

작업 브랜치는 main에서 새로 만드는 `fix/release-blockers`다. 기존 `feat/ux-round-two`의 미커밋 변경은 작업이 끝날 때까지 그대로 둔다.

## 3. 구현 항목

### M1. 2차 보완을 main에 병합

- **유지:** 한 단계 되돌리기, 화면 꺼짐 방지, 그림 미리 불러오기, 식별 지연 안내, 직원 문장 26px, 「科を選んでください」, 확대 안내문 18px, 「声を止める」, QR.
- **충돌 해결:** `entry.tsx`는 지연 안내와 PR #5의 뒤로 아이콘을 모두 살린다. `app.css`는 양쪽 규칙을 모두 둔다.
- **제거:** 높이 600px 이하의 음성·도움 한 줄 배치 CSS. PR #5의 `.aids` 구조와 맞지 않아 주 버튼을 화면 밖으로 밀어낸다. L1로 대체한다.
- 자동 읽기 토글을 높이 600px 이하의 도움 시트에서 숨기는 규칙은 유지하고, 되돌리기가 있는 시트의 높이를 다시 측정한다.

### B1. 개인정보 멈춤 화면의 잘못된 안내

| | 내용 |
|---|---|
| 현상 | 멈춤 시트를 닫으면 화면이 직전 단계를 표시해 「内科を押してください」와 「ここ」가 나온다 |
| 파일 | `screens/guidance.tsx` |
| 변경 | 멈춤 단계에서는 직전 단계를 쓰지 않는다. 제목은 `ja.safeTitle`(「ここからはご自分で」), 그림은 등록된 `s4` 장면(목표 표시 없음)을 쓴다. 키 모양과 확대 버튼을 표시하지 않는다 |
| 유지 | 주 버튼 「入力の案内を見る」로 시트를 다시 열고, 「入力しました」로만 통과한다 |
| 테스트 | E2E: 시트를 닫아도 「押してください」와 키 모양이 없고, 주 버튼으로 시트가 다시 열린다 |

### B2. 브라우저 뒤로 가기

`App.tsx`의 `popstate` 처리를 상태별로 바꾼다.

| 상태 | 동작 |
|---|---|
| 시트 열림 | 시트 닫기 (현재와 동일) |
| 촬영, 식별 중 | 취소 (현재와 동일) |
| 안내 중, 이전 단계 있음 | `BACK` 한 단계 되돌리기 |
| 안내 첫 단계 | `RETAKE` 촬영 화면으로 (취소하면 안내로 복귀) |
| 직원 화면, 돌아갈 안내 있음 | `RETURN` |
| 종료 화면, 돌아갈 안내 없는 직원 화면 | `RESTART` (현재와 동일) |

개인정보 멈춤을 앞으로 건너뛰는 경로는 없다. 테스트는 위 표의 경우별 E2E로 한다.

### B3. 태블릿 가로 화면의 모의 접수기

| | 내용 |
|---|---|
| 파일 | `styles/app.css` |
| 변경 | `.mock-kiosk .kiosk-display`의 너비를 화면 높이로 제한해 가운데에 둔다: `width:min(100%, calc((100svh - 헤더 - 푸터 - 테두리) * 304 / 276))`. 글자 크기는 `cqw` 단위라 함께 줄어든다 |
| 영향 | 세로 화면은 지금과 같다. 가로에서 남는 좌우는 기기 테두리 색으로 보인다 |
| 테스트 | E2E: 1180×820, 1024×768, 1280×800에서 버튼과 「最初に戻る」가 화면 안. 820×1180 렌더 동일 확인 |

### B4. 안내할 수 없는 이유 표시

| | 내용 |
|---|---|
| 파일 | `state/machine.ts`, `App.tsx`, `screens/entry.tsx`, `copy/ja.ts`, `content/speech.ts` |
| 변경 | `REJECTED`에 이유(`sensitive`, `unsupported`)를 넣어 상태에 저장한다. 다른 경로로 직원 화면에 오거나 다시 시작하면 지운다 |
| 화면 | 직원 화면에 이유 한 줄을 요청 문장 위에 표시한다. 이 경우 시작 화면 그림은 표시하지 않는다 |
| 음성 | 이유 문장을 도착 시 한 번 자동으로 읽는다. 자동 읽기 설정을 따른다. 요청 문장은 지금처럼 눌러야 읽는다 |
| 음원 | 새 문장 2개를 포함해 Cloud TTS로 재생성한다 |
| 테스트 | 단위: 이유 저장과 해제. E2E: `sensitive`, `unsupported` 각각 문구 표시, 일반 직원 호출에는 표시 없음 |

제안 문구:

- `sensitive`: 「この画面は個人情報があるため、案内できません。」
- `unsupported`: 「この機械には、まだ対応していません。」

### L1. 작은 화면의 보조 버튼

375×553과 360×560에서 안내 화면의 보조 버튼은 약 68px, 선택 화면은 약 62px 화면 밖에 있다. 높이 600px 이하에서만 다음을 적용한다.

| 대상 | 변경 |
|---|---|
| 안내 화면 그림 | 영역 높이를 약 68px 줄이고 그림 위치를 아래로 옮겨(`object-position` 약 40%) 「ここ」 표시를 유지한다 |
| 선택 화면 그림 | 최소 높이 88px를 약 40px로 줄인다 |
| 보조 버튼 | 최소 높이를 58px에서 48px로 줄인다 (터치 기준 48px 유지) |

글자 크기는 줄이지 않는다. 진료과 안내 단계도 함께 측정한다. 테스트는 두 크기에서 주 버튼과 보조 버튼이 화면 안에 있고, 안내 화면의 「ここ」 표시가 패널에 가려지지 않는지 확인한다.
