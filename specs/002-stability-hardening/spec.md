## 2. 요구사항

**R1 — 등록 기기 표시가 있어야 안내한다.** 문구와 배치가 같아도 「デモ用の模擬端末」 표시가 읽히지 않으면 `ok`를 내지 않는다. 제품 규칙 "등록된 기기에서만 동작한다"를 지키기 위한 것이다.

**R2 — Gemini 요청 멈춤에 대비한다.** 이미지 해상도 MEDIUM과 사고 수준 LOW를 쓴다. 6초 안에 답이 없거나 일시 오류(408·429·5xx)면 두 번째 요청을 보내 먼저 끝난 쪽을 쓴다. 전체 18초 제한은 유지한다. 요청은 최대 두 번이고, 사진을 저장하거나 사용자 모르게 재촬영하지 않는다.

Gemini 연결은 재사용하지 않는다(`Connection: close`). Mac에서 직접 호출할 때는 없던 멈춤이 Cloud Run에서 반복됐고, 동시에 보낸 두 요청이 함께 멈췄다. 재사용 연결이 원인이라는 것은 추정이며, 연결을 끄자 오류율이 약 5%에서 1.2%로 줄었다. 시도했지만 효과가 없었던 것: 순차 재시도(10·12초), CPU 항상 할당.

**R3 — 촬영 화면에서 도움 시트를 열면 음성을 멈춘다.** 시트를 닫아도 다시 읽지 않는다. 안내 화면과 같은 동작이다.

**R4 — 개발 도구 취약점을 없앤다.** vitest를 수정 버전으로 올린다. 운영 의존성 zod의 경고(high)는 이번에 고치지 않는다. 수정이 메이저 업그레이드이고 공유 스키마 전체에 영향을 주는 반면, 서버가 zod로 검사하는 입력은 저장소의 절차 파일과 크기가 작은 식별 결과뿐이다.

**R5 — 측정을 다시 할 수 있어야 한다.** `npm run api:stress -- <API 주소>`가 1장의 측정을 재현한다. 입력은 합성 화면뿐이고 파일이나 로그를 남기지 않는다.

**R6 — 실제 폰 검증 (대기).** 사람이 태블릿과 폰으로 수행한다. 이번 작업에서는 절차만 정한다.

## 5. 실제 폰 검증 절차 (R6)

태블릿에 `/mock/hospital`을 띄우고, 폰으로 실제 사용 자세로 찍는다.

1. 사진 수집: start, department, confirmation, finished는 화면별 5장씩, 개인정보 입력 화면 5장. 파일 이름은 `start-1.jpg`, `personal-input-1.jpg` 형식으로 한다. 저장소에 넣지 않는다.
2. 측정: `npm run eval:identify -w @tonari/api -- <사진 폴더>`
3. 기준(임시값): 등록 화면 20장 중 18장 이상 정답, 개인정보 입력 화면은 5장 모두 `ok` 아님.
4. iPhone Safari와 Android Chrome에서 각각 전체 흐름을 한 번 완주하고 기종, OS, 자동 음성, 카메라 거부 복구, 앱 전환을 기록한다.
